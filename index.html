Meet Mako.

The web-native model behind every workflow on this page. Most agents run on general models that were never trained to operate the web. Mako was.

TinyFish's own web-native model

Trained to operate the web, not just read it.

General models read pages. Mako runs them — it clicks, types, signs in, follows pages that change, and recovers when a step breaks. Because it learns from real production runs across hundreds of enterprise sites, it finishes multi-step work that general-model tools stall on, with far less site-by-site scripting to maintain.

Questions, answered.

What developers and enterprise buyers ask before they commit.

How is TinyFish different from other tools?

TinyFish owns a web-execution model, Mako, trained on real production web-task data. Browser-infrastructure tools and search or data APIs give you parts to assemble; TinyFish runs the model that finishes the task. One API key covers Search, Fetch, Browser and Agent.

How accurate is TinyAgent?

TinyFish publishes TinyAgent's Online-Mind2Web scores with all 300 runs open-sourced, shown in the benchmark near the top of the page. One distinction to keep straight: a task-success benchmark and a 99.99% uptime SLA measure different things.

Can agents work behind logins?

Yes. TinyVault supplies credentials so the agent can sign in, and the model never sees them. TinyProfiles keeps signed-in sessions available for reuse, and every run is recorded step by step.

What happens to our data, and do you train on it?

Credentials are isolated by TinyVault and are never exposed to the model. How your task data is handled, including retention and whether it is used to train models, is set out in enterprise agreements, so this is a question to confirm on a sales call rather than assume from the homepage.

How many agents can I run at once?

Usage-based plans run a limited number of agents concurrently; TinyFish lists two concurrent runs on the self-serve tier. Enterprise raises the limit, so if your workflows need more concurrency, that is the point to talk to the team. Confirm the current numbers with TinyFish rather than treating them as fixed.

Is it free to start?

Search and Fetch are free on every plan once you have an API key. Browser and Agent are usage-based, so you only pay for what you run, and there is no sales call required to try it.

PMM TAKE-HOME / REVIEW NOTES

Why I changed the homepage.

A homepage direction for the PMM take-home, not an official TinyFish design.

01 / Positioning

The current copy explains what the platform can do. I wanted the hero to speak to the job a customer needs done. “Other tools can’t” is still a claim to test against competitors, not a proven fact. I would soften it if the comparison data does not support it.

02 / Customer proof

I moved real results closer to the top. DoorDash, ClassPass and the benchmark each show a different kind of proof; I have kept those distinctions clear.

03 / Product discovery

I kept one interactive product preview, rather than several sections describing the same tools. Developers can explore Search, Fetch, Browser and Agent without reading a product catalog.

04 / Differentiation + trust

The hero explains the benefit without introducing Mako too early. Lower on the page, Mako explains the approach while the login example shows TinyVault and recorded runs. I left out technology claims I could not verify.

05 / Two conversion paths

Two routes, one page: an API key for developers and a sales conversation for enterprise buyers. I would measure first successful tasks, qualified inquiries and completed-workflow cost, then A/B test the hero.

Demo integrity

Supplier portals, sample product search results and login steps are illustrative interface concepts, not real customer dashboards. The source homepage and public documentation should be checked before using this concept in production. This independent mockup remains noindexed.
